# 评测脚本

三个脚本，用来量化「模型判得准不准」和「页面快不快」。技术报告第 5 节的数据就是这里跑出来的。

> 这些脚本会**真实调用模型、消耗额度**。跑一轮关系评测约 3,300 tokens。

## 前置

服务要先跑起来（本地或线上都行）：

```bash
pnpm build && pnpm start        # 本地 http://127.0.0.1:3000
```

并确保服务端已配置 Key（见 `.env.example`）。

## 三种评测

### 1. 关系判定质量

```bash
pnpm eval:relations

# 指向线上、跑 6 轮
EVAL_ENDPOINT=http://你的域名/api/relations EVAL_RUNS=6 pnpm eval:relations
```

20 条人工设计素材，含 **2 对已知矛盾、1 对重复、2 对支持、7 条无关项**。输出：

```
矛盾召回: 2.0 / 2
矛盾误报: 0.3
重复召回: 1.0 / 1
E组误连（7 条无关素材间）: 4.0
平均关系数: 13.0
平均耗时: 12.3s
平均tokens: 3302
```

关注两个数：

- **矛盾召回**必须是 2/2——漏掉矛盾，核心功能就失效
- **E 组误连**越低越好——它衡量"过度连接"

脚本最后会打印未标注的关系，方便人工复核是否可辩护。

### 2. 问答质量

```bash
pnpm eval:qa
```

4 个问题，覆盖库内可答、库内不可答、跨材料综合。脚本只打印输出，**判断需要人来看**：

- 有没有引用编号 `[1]`
- 有没有分成「库中依据 / 库外补充」
- 库内不可答时，是否老实说"素材里没有"

### 3. 首屏性能

```bash
pnpm eval:perf

# 指到线上，或用 CHROME_PATH 指定浏览器
EVAL_BASE=http://你的域名 pnpm eval:perf
```

模拟 **390×844 移动端 + 4G 网络 + 4 倍 CPU 降速**，输出落地页与工作台的 LCP、DCL、load。

## 改完提示词怎么用

1. 改 `app/api/relations/route.ts` 里的提示词
2. 重新构建并部署
3. `pnpm eval:relations` 跑同样 20 条
4. 和上一次的数字对比

**别只看单轮**——模型输出有随机性，至少跑 4 轮取平均，否则很容易把波动当改进。

## 已知的评测局限

- 20 条素材规模偏小，不能代表上百条的库
- 真值由一个人标注，存在主观性
- 只测了 DeepSeek-V4.1-Flash，换模型结论可能不同
