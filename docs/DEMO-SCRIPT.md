# 演示稿（对着当前界面走一遍）

> 用途：现场演示，或录视频前的操作预演
> 时长：约 6 分钟（现场可压到 3 分钟，见文末「速讲版」）

---

## 零、演示前 10 分钟

### 1. 把界面恢复干净

侧边栏默认**看不到**「恢复演示数据」——它被开关隐藏了。要重置：

```
/kb/settings → 打开「显示「恢复演示数据」入口」
→ 回工作台 → 点「恢复演示数据」
→ 再回设置页把它关掉（避免演示时误点）
```

### 2. 先把冲突算出来（关键）

冲突不是预置数据，必须由云端判定产生。**现场才算要等 12–20 秒**。

```
关联页 → 点「云端重算」→ 等 15 秒左右
→ 冲突页出现 1 条待处理（Copilot vs METR）
```

算完会存进浏览器，之后打开就有。

### 3. 检查模型

```
/kb/settings → 「测试连接」→ 看到绿字
```

主模型 `deepseek-flash` 本身支持图片，「视觉模型」三栏留空即可。

### 4. 环境

- [ ] `pnpm demo` 已启动（或直接开线上地址）
- [ ] 浏览器缩放 100%，窗口最大化
- [ ] 隐藏书签栏（Ctrl+Shift+B）
- [ ] 关掉通知、微信、其他标签页
- [ ] 手机演示：同一 Wi-Fi，访问 `http://8.163.104.134`

## 一、开场（30 秒）

**画面**：落地页 `/`

> 现在工具很多，但收藏不等于学会。我在短视频软件里收藏了几百条，
> 进收藏夹之后就再没打开过——有些甚至没看完。
>
> 问题不在找不到，而在**收藏这个动作本身就给了「我已经获得了」的错觉**。

如果对方好奇：点「查看产品演示」，四步弹窗把产品讲完了。

---

## 二、定位（40 秒）

**画面**：`/kb` 知识库

> 所以我做的不是又一个收藏工具，而是解决收藏之后的事。
> 一句话：**AI 负责让你看清，不负责替你想清楚**。
>
> 它盯三件事：

指屏幕：

> 存了不看——收件箱一直挂着没消化的素材；
> 看了不写——必须先写一句「为什么存它」才算消化；
> 写了不判断——素材矛盾时模型标出来，但**必须你自己决定**。

---

## 三、入库与意图门（50 秒）

**画面**：收件箱

> 这里有 1 条未消化。它没有「为什么存它」，所以进不了知识库。

**操作**：点「让模型帮我想」

> 模型读这条材料，给三个可能的收藏理由——但**它不替你决定**。

**操作**：点一条建议 → 填进输入框 → 点「消化」

> 消化之后才进知识库，并且带着理由。

---

## 四、缺口检测（40 秒）

**画面**：缺口

**操作**：输入

```
写一篇关于 AI Agent 落地现状的综述
```

> 它先算覆盖率——现在大概 17%，然后指出哪三个方向没有证据。

指屏幕：

> 这不是打分，是**缺口清单**。写着写着发现没材料，比写完才发现好。

---

## 五、冲突：核心（90 秒）

**画面**：冲突

> 这两条是矛盾的：一条说 Copilot 让任务快 55.8%，一条说 METR 实测反而慢 19%。

**操作**：点「让模型说清分歧，并可追问」

> 模型会说清它们争的其实是**前提不同**——受控任务 vs 真实仓库，还能继续追问。

**操作**：选「采纳前者」→ 写一句判断 → 确认

> 注意：**它没有删除另一条**。被取代的那条打包并入前者，标着「已并入对方」。

**画面**：切到「文件夹」

> 反方证据收在这里，随时能翻回来对照，详情页能直接跳到对方。

**说**（重点）：

> 如果不做这一步，模型会把我库里两个矛盾的说法，缝成一段自洽但错误的总结。

---

## 六、问答：两段式（60 秒）

**画面**：问答

**操作**：问一个库里没有的问题

```
大学应该学 AI 学什么？
```

> 库里没有相关内容。但我不想让它就此闭嘴，所以可以让模型补充背景。

**操作**：点「让模型补充背景」

> 答案分两块：**库中依据**每句带出处；**库外补充**单独一块，
> 用琥珀色标出来「不在你的素材里」。

**操作**：点「让模型找几篇能补上的材料」

> 它推荐真实的公开材料——CS2023、AIMA、CS229。
> 加不加由我决定。点一下会抓正文并入库，自动写入收藏理由。

---

## 七、图谱（40 秒）

**画面**：关联

> 每加一条素材都会重算关系。本地算法算词面相似；
> 点「云端重算」升级成模型判定：支持、矛盾、重复、相关，并给一句理由。

**操作**：拖一下旋转，点一个节点

> 点节点打开原文，右侧只列这条素材的关系。

---

## 八、收尾（40 秒）

> 三个技术取舍：
>
> 一，**数据只存在浏览器**，不上传、不需要账号；
> 二，**云端全部可降级**——没 Key、断网时，检索、缺口、简报、图谱照样能用；
> 三，**出错可诊断**——错误条带「复制」，一键拿到时间、接口、状态码。

**可选**：打开 `/kb/metrics`

> 服务端只记宏观指标：延迟、成功率、错误分布，不记用户内容。

**收尾句**：

> 一句话：**AI 负责让你看清，不负责替你想清楚。**

## 可能被问到的问题

| 问题 | 回答要点 |
|---|---|
| 和 Notion / Obsidian 有什么不同？ | 它们管「存和看」，我管「存完有没有想清楚」。缺口和冲突是它们没有的 |
| 数据存在哪？ | 浏览器 localStorage，不上传。换设备会丢，这是已知限制，有导出备份 |
| 用了哪些模型？ | 任何 OpenAI 兼容端点，默认 DeepSeek-V4.1-Flash（文本 + 图片） |
| 会不会瞎编？ | 回答分两段：库内每句带引用，库外单独标注，不混在一起 |
| 冲突检测准吗？ | 20 条素材实测：已知矛盾 2/2 检出；代价是泛相关判得偏松 |
| 为什么不做账号？ | 短周期内保证不了数据安全；也避免托管用户的 API Key |
| 一个人做的？ | 是。前端、后端、算法、视觉都是自己写的 |
